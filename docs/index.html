When training data is wrong, what actually wins the accuracy back?

Wrong labels and missing values are in almost every real dataset. This study corrupts clean data in controlled ways, applies detection and repair methods, retrains, and measures against the ground truth, so every claim comes with a confidence interval.

Method

Four steps, repeated 1,428 times

Because the corruption is applied on purpose, the study knows exactly which rows are broken. That turns "does this cleaning method help?" into something that can be measured.

1

Corrupt

Flip 0–40% of training labels, or blank 10–30% of cells (MCAR random, or MNAR where large values go missing). Keep a ground-truth mask.

2

Detect

Out-of-fold probabilities from K-fold CV, then confident learning (per-class thresholds) vs a simple "model disagrees" rule.

3

Repair

Prune flagged rows (never a whole class), or impute with mean · median · KNN · iterative, with or without missing-indicator features.

4

Evaluate

Retrain, score on an uncorrupted test set, repeat over 5 seeds, report mean ± 95% CI and a paired t-test vs. no repair.

Does the detector find the right rows?

Label noise 20%
Precision vs recall. Confident learning is the more precise detector, but the simple rule catches more of the wrong labels. When the repair is "drop the flagged rows", a missed wrong label costs more than a dropped clean one, so higher recall often wins on accuracy. If flagged rows go to a human reviewer instead, precision is what matters.

Reproduce

Run it yourself

Everything runs offline on scikit-learn's bundled datasets. The full study takes about 30 minutes on a 2-core laptop, and every chart on this page can be rebuilt from the CSVs it writes.

# install and test
pip install -r requirements.txt
pytest                      # 20 unit tests

# run the study
python run.py --quick       # ~2 min smoke run
python run.py               # full study, ~30 min

# rebuild the report and this page
python report.py
python site/build_site.py
